1) 192.168.10.0/24 แบ่งเป็น 8 Subnets เท่ากัน

    a) Subnet Mask ที่ต้องใช้
        เพื่อแบ่งเป็น 8 subnets ต้องยืม 3 บิตจาก Host portion (2^3 = 8)
        New prefix = /24+3 = /27
        Subnet Mask = 255.255.255.224

    b) จำนวน Usable Host Addresses ต่อ Subnet
        Host bits = 32−27 = 5 บิต
        Usable hosts = 2^5−2 = 32−2 = 30 hosts ต่อ subnet

    c) Network Address

2) 172.16.0.0/20 ต้องการ >=10 Subnets, >=200 Hosts/Subnet    
    
    a) Subnet Mask ที่เหมาะสมต้องรองรับ >=200 hosts ดังนั้น host bits = 8(2^8−2=254>=200)
        New prefix = /24, Subnet Mask = 255.255.255.0
        บิตที่ยืม = 24−20 = 4 บิตดังนั้ง 2^4 = 16 subnets >= 10

    b) จำนวน Subnets ทั้งหมด
        16 subnets

    c) Usable Hosts ต่อ Subnet
        2^8−2 = 254 hosts

    d) Network Address ของ 10 Subnets แรก

4 192.168.1.0/24 ออกแบบด้วย CIDR

    a) การแบ่งเดิมแบบ /26 (62 usable hosts ต่อ subnet) รองรับได้หรือไม่?
       ไม่สามารถรองรับได้ /26 มี usable hosts 2^6−2 = 62 hosts/subnet
       Department A ต้องการ 110 hosts ซึ่งมากกว่า 62 เลยไม่พอ

    b) ปัญหาหาก Department A ได้รับ /26 subnet หนึ่ง subnet?
       Department A มี 110 hosts แต่ /26 รองรับได้เพียง 62 hosts
       Host ส่วนที่เกิน 62 เครื่อง จะไม่สามารถ assign IP address ได้ในวง subnet เดิม
       ส่งผลให้ต้องใช้หลาย subnet หรือระบบทำงานไม่ครบ

    c) CIDR เป็นทางเลือกที่ดีกว่าหรือไม่?
       ถูกต้องเพราะ CIDR ช่วยให้ subnet ขนาดต่างกันตามความต้องการจริงของแต่ละ department
       ลดการสีย IP address และใช้ address space ได้ดีกว่า Fixed-length subnetting

    d) Solution ด้วย CIDR (192.168.1.0/24)
        Department	    Req.	Network Address	Prefix	Subnet Mask
        Department A	110	    192.168.1.0	    /25	    255.255.255.128
        Department B	50	    192.168.1.128	/26	    255.255.255.192
        Department C	25	    192.168.1.192	/27	    255.255.255.224
        Department D	10	    192.168.1.224	/28	    255.255.255.240

        Department	    First Host	    Last Host	    Broadcast	    Usable
        Department A	192.168.1.1	    192.168.1.126	192.168.1.127	126
        Department B	192.168.1.129	192.168.1.190	192.168.1.191	62
        Department C	192.168.1.193	192.168.1.222	192.168.1.223	30
        Department D	192.168.1.225	192.168.1.238	192.168.1.239	14

    e) IP Addresses ที่เหลือไม่ได้ใช้งาน
       Addresses ที่ใช้ไปคือ 128+64+32+16 = 240 addresses
       Addresses ที่เหลือคือ 256−240 = 16 addresses (192.168.1.240 – 192.168.1.255)

    f) เหตุใด Address Utilization จึงสำคัญ?
       IPv4 มี address space จำกัดประมาน4.3 พันล้าน addresseห และปัจจุบันหมดไปแล้ว
       การออกแบบที่ดีช่วยลดการเสีย address โดยไม่จำเป็น
       ช่วยลดต้นทุนโดยเฉพาะ Public IP และยืดอายุการใช้งาน address pool ขององค์กร

    g) รองรับ Department A ที่เพิ่มเป็น 200 hosts ได้หรือไม่?
       ไม่ได้เนื่องจาก /25 ปัจจุบันรองรับ 126 usable hosts ซึ่งไม่พอสำหรับ 200 hosts
       แนวทางที่กระทบระบบเดิมน้อยที่สุดคือ
          -ขยาย subnet ของ Dept A จาก /25 เป็น /24 โดยใช้ block ใหม่ เช่น 192.168.2.0/24
           (ขอ block เพิ่มจาก ISP/ผู้ดูแล หรือใช้ Private range เพิ่มเติม)
          -ทำ Supernetting: รวม 192.168.1.0/25 และ 192.168.2.0/25 ให้เป็น /24 ตัวเดียว
          -ระยะยาว: พิจารณาย้ายไปใช้ IPv6 ซึ่งมี address space ไม่จำกัด
